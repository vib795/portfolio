How I evolved a weekend project into a complete private media and privacy stack — with Go CLI tools, Plex, Tailscale, Pi-hole, and a purpose-built travel router

About a year ago, I wrote about turning a Raspberry Pi 3B+ into a secure travel router. The idea was simple: stop trusting hotel and cafe Wi-Fi, route everything through a device you control. It worked well enough on a 10-day road trip — but it was high-maintenance, fragile, and left me wanting more.

That project turned out to be the first domino. Once I had a taste of owning my network, I kept going. Over the following months, I built out a complete self-hosted home lab that now handles everything: private video streaming, network-wide ad blocking at the DNS level, and secure access to all of it from anywhere in the world.

This post is the full story of what that stack looks like today.

The Problem I Was Actually Solving

Every developer eventually reaches a point where the subscriptions, the ads, and the background telemetry start to feel like death by a thousand cuts. YouTube Premium to skip ads on a browser. Plex Pass just to watch your own files remotely. A VPN subscription because you don’t trust hotel Wi-Fi. Browser extensions that only protect one browser on one device.

The data is eye-opening once you look at it. My Pi-hole dashboard shows roughly 30% of all DNS queries on my home network are ads, trackers, or background telemetry — not from websites, but from apps, smart TVs, and devices just running in the background.

I wanted one coherent system that handled all of this, ran on hardware I already owned, and cost nothing to maintain month to month.

Here’s what I built.

The Full Stack

pull-vids (download)
    ↓
convert-vid (convert to any format)
    ↓
Plex on Mac Mini (private media server)
    ↓
Tailscale (mesh VPN — private access from anywhere)
    ↓
Pi-hole on Raspberry Pi 5 (DNS ad blocking everywhere)
    ↓
GL-MT3000 travel router + Tailscale (home network on the go)

Let me walk through each piece.

Part 1: pull-vids — Download Any Video in One Command

I built pull-vids as a Go CLI that wraps yt-dlp, the gold-standard open-source video downloader. yt-dlp is incredibly powerful but the syntax is verbose and hard to remember. A typical quality download looks like this:

yt-dlp -f "bestvideo[height<=1080]+bestaudio/best[height<=1080]" \
  --merge-output-format mp4 \
  -o "%(title)s.%(ext)s" \
  "https://youtube.com/watch?v=..."

With pull-vids, that becomes:

pull-vids "https://youtube.com/watch?v=..." -q 1080p

Install

brew install vib795/tap/pull-vids

Key Commands

# Download at specific quality
pull-vids "URL" -q 1080p
pull-vids "URL" -q 720p
# Extract audio only (great for podcasts)
pull-vids "URL" --audio-only
# Download an entire playlist
pull-vids "https://youtube.com/playlist?list=..." -q 720p
# Custom output directory
pull-vids "URL" -q 1080p -o ~/Videos/tutorials

Downloads land in ~/Downloads/pull-vids by default, which is the same folder Plex watches. You download a video and it shows up in your library automatically — no manual moving of files.

The tool is built in Go, distributed via my Homebrew tap using GoReleaser and GitHub Actions. Every git tag push builds cross-platform binaries for macOS (Intel + ARM), Linux, and Windows and auto-updates the Homebrew formula.

GitHub: github.com/vib795/pull-vids

Part 2: convert-vid — Batch Format Conversion Without Memorizing ffmpeg

convert-vid wraps ffmpeg with a clean interface. Instead of remembering codec flags and CRF values:

ffmpeg -i input.mov -c:v libx264 -crf 23 -preset medium \
  -c:a aac -b:a 128k output.mp4

You just run:

convert-vid convert input.mov -f mp4 -q medium

Install

brew install vib795/tap/convert-vid

Key Commands

# Single file
convert-vid convert input.avi -f mp4
convert-vid convert input.mov -f mp4 -q high
convert-vid convert input.mov -f mp4 -q low    # Smaller file size
# Filenames with spaces — use --input flag
convert-vid convert --input "My Video File.webm" -f mp4
# Batch convert an entire folder
convert-vid convert ./videos -f mp4
# Batch with 4 concurrent workers (faster)
convert-vid convert ./videos -f mp4 -c 4
# Batch with output directory
convert-vid convert ./videos -f mp4 -q high -o ./converted -c 2

Supported formats: mp4, mkv, webm, avi, mov, flv

Quality presets map to ffmpeg’s CRF values internally — high = CRF 18, medium = CRF 23, low = CRF 28. You get the right output without needing to know what any of that means.

GitHub: github.com/vib795/convert-video-formats

Part 3: The Download → Convert Pipeline

The two tools connect naturally. I have a shell wrapper called pull-and-convert that runs the full workflow:

  1. Download with pull-vids
  2. Prompt: convert? y/n
  3. If yes: pick format and quality
  4. Run convert-vid automatically
  5. Prompt: delete original?
pull-and-convert "https://youtube.com/watch?v=..." -q 1080p

I also have two batch Python scripts using the modern uv tool with PEP 723 inline dependency declarations — no virtualenv, no pip install, just uv run:

# Bulk download from a text file of URLs
uv run batch_pull_vids.py urls.txt
# Bulk convert an entire folder
uv run batch_convert_vids.py ~/Downloads/pull-vids mp4 medium

PEP 723 lets you declare dependencies directly in the script file:

# /// script
# requires-python = ">=3.11"
# dependencies = ["yt-dlp", "tqdm"]
# ///

uv run handles the rest. It's a genuinely elegant pattern for standalone utility scripts.

Part 4: Plex on Mac Mini — Your Private Media Server

Plex Media Server runs natively on the Mac Mini — no Docker, no containers, just the Plex app installed directly on macOS. It’s always on, low power, and pointed at ~/Videos, the same folder that pull-vids writes to.

When you download a new video, Plex picks it up automatically, pulls in metadata and artwork, and makes it available to stream on any device through the Plex app or at app.plex.tv.

The most important part: no Plex Pass required for remote access.

Normally, accessing Plex outside your home network requires either Plex’s relay servers (which require a Plex Pass subscription) or complicated port forwarding. Tailscale eliminates both. Because the Mac Mini is a Tailscale node, Plex sees any connection from a Tailscale-connected device as a local connection. It streams directly, peer-to-peer, with no subscription and no relay.

Part 5: Tailscale — Your Entire Home Network, Accessible Anywhere

Tailscale is a mesh VPN built on WireGuard. It connects all your devices — Mac Mini, Raspberry Pi, phone, laptop — into a private network called a tailnet. Every device gets a stable private IP address in the 100.x.x.x range.

No port forwarding. No dynamic DNS. No public IP exposure. No company in the middle logging your traffic. The personal plan is completely free for up to 100 devices.

Install on Mac Mini

# Via Homebrew
brew install tailscale
# Or download from tailscale.com
sudo tailscale up

Install on Raspberry Pi

curl -fsSL https://tailscale.com/install.sh | sh
# IMPORTANT: use --accept-dns=false on the Pi
# (the Pi is your DNS server — you don't want it using itself as upstream)
sudo tailscale up --accept-dns=false

Once running, check your tailnet in the Tailscale admin console. Every device shows up with its stable 100.x.x.x IP. Plex on the Mac Mini is now accessible at http://100.x.x.x:32400 from any device on the tailnet — phone on cellular, laptop at a coffee shop, anywhere.

One config tip: In the Tailscale admin console, disable key expiry for your Mac Mini and Raspberry Pi. By default, keys expire after 6 months. For always-on servers, you don’t want them dropping off the tailnet.

Part 6: Pi-hole on Raspberry Pi 5 — Block Ads on Every Device, Everywhere

Pi-hole is a DNS sinkhole. Instead of running inside a browser, it intercepts DNS queries at the network level and drops any request that matches a known ad, tracker, or telemetry domain. The result: every device on your network gets ad blocking — phones, smart TVs, IoT devices, apps — without any extensions or per-device configuration.

Running it on the Raspberry Pi 5 with Tailscale as the integration layer means this protection extends beyond your home network. Any device connected to your tailnet — on cellular, at a hotel, traveling — uses your Pi-hole as its DNS server.

Install Pi-hole

# Set a static IP for the Pi first (via router DHCP reservation)
# Then run the installer:
curl -sSL https://install.pi-hole.net | bash

The installer walks you through selecting an upstream DNS provider (I use Cloudflare 1.1.1.1), setting up the web interface, and confirming your static IP.

Access the dashboard at http://pi.local/admin or http://PI_IP/admin.

Post-Install Setup

# Change the admin password
pihole -a -p
# Update blocklists
pihole updateGravity

Recommended blocklists (add in Pi-hole → Adlists):

  • StevenBlack unified list — included by default, excellent baseline
  • OISD Big: https://big.oisd.nl
  • HaGeZi Multi PRO: https://raw.githubusercontent.com/hagezi/dns-blocklists/main/adblock/pro.txt

Connect Pi-hole to Tailscale for Global Ad Blocking

This is the step that makes Pi-hole useful everywhere, not just at home:

  1. Get your Pi’s Tailscale IP from the admin console (e.g., 100.64.0.2)
  2. In Pi-hole: Settings → DNS → set listening interface to tailscale0, set listening behavior to "Permit all origins"
  3. In Tailscale admin console: DNS tab → Add nameserver → enter 100.64.0.2 → enable "Override local DNS"

That’s it. Every device on your tailnet now uses Pi-hole for DNS, regardless of what network they’re physically connected to.

Part 7: The Travel Router — The Setup That Started It All, Upgraded

Back in 2024 I built a Raspberry Pi 3B+ travel router using RaspAP. It proved the concept but required too much maintenance — OS updates, manual configuration, and occasional breakage at the worst possible times (mid-trip).

The GL-MT3000 (Beryl AX) replaced it. It’s a purpose-built travel router that runs OpenWrt and supports Tailscale natively through its app store — install the Tailscale plugin, log in to your tailnet, and you’re done.

The difference in practice: plug the GL-MT3000 into any hotel or cafe ethernet or Wi-Fi, connect your devices to it, and the entire network runs through your tailnet. Plex streams from the Mac Mini. Pi-hole filters every DNS query. Everything works exactly as it does at home, no matter where you are.

The Pi 3B+ is still running — just not as a travel router anymore. It’s in the homelab doing other things.

The Numbers

After running this stack for a while, the Pi-hole dashboard tells a clear story:

  • Roughly 40–50% of all DNS queries on my network are blocked
  • The worst offenders are apps and smart TVs, not websites
  • That’s thousands of blocked requests per day from background telemetry you never asked for and never knew was happening

The Tailscale + Pi-hole combination means this isn’t limited to my home. My phone blocks the same percentage of queries whether I’m at home, in a hotel, or on cellular — because it’s always using Pi-hole as DNS over Tailscale.
